# ADR 工作方法

以项目根目录的 `AGENTS.md` 为工作约定，`docs/adr/index.md` 为决策入口，`docs/adr/template.md` 为文档格式。所有路径相对项目根目录。

## 判断是否记录

只有未来维护时需要解释原因、改变方向有明显成本或会约束后续实现的选择才建立 ADR。先查阅相关有效记录，避免重复记录同一决策。

## 创建与维护

1. 检查目录内已有编号，选择未使用的四位编号，创建 `docs/adr/NNNN-<topic>.md`。按照模板记录真实问题、候选方案、结论和代价；证据不足的内容明确标注。
2. 有待定取舍时保持 `proposed`。已有用户授权且方案已明确时可写 `accepted`，不重复索取同一授权。不得虚构批准或把未验证结果写成事实。
3. 在索引登记决策并维护可解析的相对链接。存在任务记录时，从其 `Related ADRs` 引用决策；不存在时无需补建任务。
4. 新决策替代旧决策时，保留旧正文，新建记录并更新双方的替代关系及索引。明确不采用的方案可标记 `rejected`；停止推荐但无替代时使用 `deprecated`。
5. 如果产生后续实现需要持续遵守的约束，更新 `docs/spec/` 对应文档及索引，并从 ADR 引用；不要复制整篇理由或强制创建规范。

## 交付检查

检查编号唯一、状态与已知授权一致、替代关系双向一致、链接可解析。说明记录了什么决策、依据和未解决事项。不自动提交、发布或创建流程状态。
