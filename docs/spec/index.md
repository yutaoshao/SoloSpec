# 项目规范

这里记录系统当前有效的行为、业务规则和必要技术约束，让读者按领域理解系统在做什么，而不需要先阅读源码。不要复制通用开发常识，也不要根据模板猜测技术栈或测试命令。

## 规范入口

当前尚无项目特有规范。根据真实代码、已接受决策和已验证行为，按模块或领域创建文档并登记：

| 领域 | 规范文档 | 适用范围 |
| --- | --- | --- |

功能说明可从 [功能说明模板](../templates/feature.md) 开始。它按需说明用途、角色与权限、入口、流程、关键规则、数据或状态变化、主要异常结果和核查依据；不要求机械填写不适用章节。检查命令必须有项目依据；暂不可运行时明确原因。

## 维护方式

- Agent 按影响范围从本索引读取，不要求全量加载。
- ADR 负责解释选择的原因；规范直接说明当前有效行为和约束，并可链接相关 ADR 作为背景。
- 实现改变了对使用者、管理员、外部系统或其他模块可观察的行为、规则或重要约束时，同步修正文档；不必等待规则稳定。行为不变的内部重构通常不更新业务说明。
- 当前结论不得只放在 ADR、任务记录或源码链接中；这些链接只用于追溯和核查。
- 频繁的小需求维护原有领域文档，避免按每次修改拆分出多个说明；Git 历史保留演变过程。只有出现重要长期取舍时才新增 ADR。
- 任务特有的步骤和未完成事项留在任务记录，不写成永久规范。
