# SoloSpec

[English](README_EN.md) | [中文](README.md)

**给个人开发者的轻量 AI 项目约定：保存决策和必要知识，让日常开发保持简单。**

SoloSpec 是一组 Markdown 规则与模板。它不调度 Agent、不管理进程、不维护任务数据库，也不要求安装运行时。核心流程只有四步：读约束 → 按需记录 → 实现验证 → 交付沉淀。

## 开始使用

已有项目可以直接使用下面的接入提示词，让 Agent 获取模板并合并规则。若希望手动接入，将 `AGENTS.md`、`docs/` 和 `templates/` 中需要的内容合并到项目；可选 ADR 技能位于 `.agents/skills/adr-workflow/`。已有同名文件时先阅读再合并，保留项目原有内容。

接入完成后，直接向 Agent 描述你要做的事情。Agent 会按项目约定读取相关规范、执行并验证；只有需要跨会话继续、包含多个有依赖的实施阶段，或你明确要求记录时，才创建任务文档。

能发现 `AGENTS.md` 的工具可直接读取；其他工具需在自己的项目指令入口引用它。模板提供行为约定，不会强制工具执行。

规则和文档模板默认使用中文。接入时可改为目标项目的文档语言，并保持路径、代码、状态值及引用一致。

## 已有项目：让 Agent 帮你接入

在目标项目中打开支持联网读取或 Git 克隆的 Agent，直接发送以下提示词，无需先手动下载。模板来源是 SoloSpec 仓库，写入目标是当前打开的项目。

```text
请将 SoloSpec 接入当前项目。

模板来源：https://github.com/yutaoshao/SoloSpec
目标：当前项目根目录。

读取仓库默认分支中的模板文件；可以下载或克隆到目标项目之外的新临时目录，作为只读来源。不要把当前项目替换成模板仓库，也不要复制模板的 .git 目录。若来源无法访问，报告具体原因并请求可访问的链接或本地模板路径，不根据猜测创建模板内容。

先阅读目标项目已有的 AGENTS.md、相关项目指令和文档结构，再执行接入：
1. 将模板的四步工作方式、任务记录与 ADR 约定合并到项目规则中。保留已有规则，去除重复表述；实质冲突以目标项目约定为准，无法确定时说明冲突并澄清，不静默覆盖。
2. 补充缺失的 ADR、规范、任务入口和任务模板。已有规范或 ADR 目录时优先沿用，统一修改接入规则、模板和可选技能中的目录约定与引用，不创建第二套事实来源。旧任务保留原位置和格式，并登记其入口。
3. 文档沿用目标项目的语言，按需翻译模板提示文字，保留路径、代码和状态值。只根据实际代码和已有文档登记规范与检查命令；信息不足时明确留空，不虚构技术栈、决策或测试结果。
4. 工具支持项目级技能时，接入 .agents/skills/adr-workflow/；已有同名技能则检查后合并。工具不支持时使用 AGENTS.md 和 ADR 模板即可，不安装额外运行时。
5. 保留目标项目的 README、LICENSE、Git 历史及无关文件，不把 SoloSpec 的项目介绍或许可证覆盖到目标项目；复制模板内容时保留所需的 MIT 许可声明。
6. 不引入 hook、任务数据库、阶段审批或自动提交；不为接入而批量迁移历史文档。

完成后检查相对链接与路径引用，并核对：简单任务不建记录、复杂任务有固定位置、新会话能按目标续接、长期决策进入唯一 ADR 目录。
报告新增与修改的文件、沿用的目录、验证结果及未解决事项。不提交或推送 Git。
```

此提示词授权 Agent 修改当前项目中的接入文件；使用前确认打开的是目标项目。若使用自己的 fork，替换模板来源链接即可；离线接入可将链接替换为已有模板的本地绝对路径。若只想评估，把首句改为“请只评估 SoloSpec 如何接入当前项目，给出文件变更建议，不修改文件”。

## 三类文档

| 内容 | 位置 | 记录时机 |
| --- | --- | --- |
| 决策及取舍 | `docs/adr/` | 出现影响长期维护的设计选择时 |
| 稳定约束 | `docs/spec/` | 产生后续实现需要持续遵守的规则时 |
| 任务与交接 | `docs/tasks/YYYY-MM-DD-<topic>/task.md` | 跨会话、多阶段任务，或明确要求保留计划时 |

ADR 解释原因，规范描述约束，任务记录保存当前进展。通过链接关联，不重复抄写。

## 使用场景

- **修正文案或局部错误**：读取相关约束，修改并验证，不新建任务文档。
- **分阶段更换存储方案**：按需创建任务记录；查阅相关 ADR，在长期方案明确后记录决策及必要规范。
- **继续上次未完成的工作**：优先采用明确路径，否则按目标和下一步匹配记录；歧义时询问，不猜“最新任务”。
- **记录项目级决策**：直接创建 ADR，不为了配套而制造任务文档或新规范。

## 仓库内容

```text
AGENTS.md                         工作约定入口
LICENSE                           MIT 许可
README.md                         中文使用说明（默认）
README_EN.md                      English guide
docs/adr/index.md                 决策索引
docs/adr/template.md              决策模板
docs/spec/index.md                项目规范入口
docs/tasks/README.md              任务位置与旧项目接入说明
templates/task.md                 任务模板
.agents/skills/adr-workflow/       可选 ADR 技能
```

文档放在可见的 `docs/` 中，方便人和不同工具查阅。没有隐藏运行状态；停用 SoloSpec 后，这些文档仍属于你的项目。

## 范围与可选工具

没有强制 Brainstorm、阶段审批、固定多 Agent 流程、会话记账或自动提交。需求追问、历史会话检索和代码审查由你按需选用工具；核心模板不依赖它们。

本模板适合个人开发与维护。多人协作时可以补充责任与评审约定，但不应为了可能的未来需求预先增加流程。

## 发布自己的副本

你可以 fork 或下载此仓库，发布自己的模板。发布时将两份 README 接入提示词中的模板来源替换为自己的仓库地址。模板的决策与规范入口初始为空，由使用者根据真实项目补充；不要把产品项目的历史记录混入通用模板。

## 来源与许可

SoloSpec 的设计来自对个人项目文档工作方式的整理，也受到 Trellis 的“规范与任务持久化”思路启发。本仓库的规则、模板和技能正文独立编写，未打包 Trellis 的代码、技能、模板正文或运行设施；不依赖 Trellis。
